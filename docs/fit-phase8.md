# Phase 8: Scatter + symmetric Y Error + native Linear Fit

The chart type remains `xy_scatter`. The existing series contract stores `Y_SD` under `render_spec.data.y_errors.Y`; the optional Phase 6 `FitSpec` separately binds X/Y and specifies `weight_mode="none"`. No combined renderer or new FitResult schema was added. Production scope is one X, one Y, one symmetric Y SD column, full range, free slope/intercept, and a native linear fit.

Grapher's existing XY loop attaches `ErrorBars` to the Scatter plot, then `AutoLinePlot.AddFit(0)` to that same plot. After GRF reopen, verification reads the separate error binding, invisible Scatter connecting line, `AutoFitPlot` source and range, native statistics, and the two-entry data/Fit legend. Keep the GRF with its staging CSV.

Origin's existing Scatter worker adds the native Y error plot. `OriginEngine` then attaches the Phase 7 native `FitLinear` analysis and its curve to that OPJU. Origin 2024 preselects the plotted Y error dataset and defaults `Fit.ErrBarWeight` to instrumental `1/e²` even when `LinearFit.set_data` supplies only X/Y. The Fit capability explicitly sets this native GUI-tree property to `0` (No Weighting) before `report()`. Without it, this fixture changed slope from `1.97` to about `1.977`. Saved OPJU verification reopens a copy and checks native Scatter/Y-error datasets, the FitLinear report and curve, X/Y source binding, range, and result. It independently compares native coefficients to an unweighted regression on the source X/Y data. This comparison is a verification gate; the reported FitResult values still come from Origin.

Origin's automatic linked legend adds duplicate fit entries after `FitLinear.report()`; the combined output removes that misleading legend. Grapher retains `Y` and `Linear Fit - Y`. Neither backend draws a connecting line through the Scatter points. The existing Origin axis-title style and Fit statistics table remain under the Origin template's control.

On `(X,Y) = (1,2.1), (2,4.0), (3,6.2), (4,8.1), (5,9.9)` with SDs `0.20, 0.25, 0.30, 0.22, 0.28`, Error+Fit and Fit-only results match within each backend: Origin slope `1.9700000000000002`, intercept `0.14999999999999947`, R² `0.9988932358694533`; Grapher slope `1.97`, intercept `0.15`, R² `0.99889324`. `result_source` is `backend_native` in both. Origin's report text is locale-dependent, so `weighting_readback` remains marked unsupported; the explicit native setting and numeric comparison establish this route's unweighted behavior.

The two real composition tests in `tests/test_fit_integration.py` render Fit-only and Error+Fit plans, save, reopen, read back, verify, and compare native results. Existing Fit-only tests remain; all four real Fit integration tests passed. All ten existing Grapher GUI integration tests passed, as did 976 non-GUI tests (7 skipped, 17 GUI tests deselected). Independent `verify --engine origin` and `verify --engine grapher` calls passed on the final directories. The pre-existing Origin Scatter+Error project without Fit also passed independent verification. Generated final projects live in `.phase8-production/origin` and `.phase8-production/grapher`; Origin also exports TIF. The user opened both native projects in their respective applications and confirmed the Phase 8 GUI cross-edit checks were normal, including editable Error/Fit objects and Grapher legend. This is user-reported GUI acceptance, separate from automated native readback.

This phase does not implement weighting, partial ranges, multiple series, polynomial models, or nonlinear models. Origin's installed FitLinear GUI tree and the [Origin weighting guide](https://docs.originlab.com/origin-help/fit-with-err-weight/) document the distinction between an error column and a weighting policy.
